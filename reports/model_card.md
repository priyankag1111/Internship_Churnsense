## Intended Use

Use this model for educational analysis and as a decision-support signal to prioritize further investigation of potential churn. It is not validated for automated customer treatment, pricing, service denial, or production deployment.

## Data and Processing

The model was trained on `data/raw/Customer_churn.csv`. `customerID` is excluded. `TotalCharges` is parsed numerically; missing numeric values are median-imputed, categorical values are most-frequent-imputed, numeric features are standardized, and categorical features are one-hot encoded. The `tenure_monthly_charge_ratio` and `long_term_customer` features are added. Preprocessing is fit within the model pipeline and within each cross-validation fold.

The stratified split contains 5,634 training rows and 1,409 test rows. The test set contains 374 churn cases. The held-out split was used for final reporting, not model selection.

## Performance

The selected pipeline achieved a 3-fold training CV ROC AUC of 0.8509 during randomized tuning and a held-out test ROC AUC of 0.8476. At the default 0.50 threshold, held-out precision for churn was 0.6781, recall was 0.5294, and F1 was 0.5946. Its confusion matrix is 941 true negatives, 94 false positives, 176 false negatives, and 198 true positives.

The five baseline candidates' held-out ROC AUC values were: Gradient Boosting 0.8428, Logistic Regression 0.8416, Random Forest 0.8240, Extra Trees 0.7954, and Decision Tree 0.6296. An additional CatBoost candidate was evaluated using training-only cross-validation and did not exceed the baseline CV leader.

## Limitations and Risks

The test ROC AUC is below the requested >0.85 target; performance should not be represented as meeting that target. Results are from a single random split of this dataset and may not generalize to other customers, time periods, or operating conditions. Churn errors have different business costs: at the current threshold, 176 of 374 churners were missed. Threshold selection and cost-sensitive evaluation require business input and should use validation data, not repeated tuning against the held-out test set.

No subgroup fairness, calibration, temporal validation, drift, or causal analysis has been performed. Explanations from SHAP describe model associations and are not causal reasons for customer behavior.
